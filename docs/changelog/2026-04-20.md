# 2026-04-20 作業ログ

## Vercel April 2026 セキュリティインシデント対応

[Vercel Bulletin](https://vercel.com/kb/bulletin/vercel-april-2026-security-incident): Context.ai経由でVercel社員のGoogle Workspaceが侵害され、一部顧客の「Sensitiveマーク無しの環境変数」が露出した可能性。

### 調査結果

対象プロジェクト:
- `trails_jp`: env 7件、**全て "Encrypted"（Sensitiveフラグ無し）** → 全件が露出候補
- `app` (parkingmeter-tokyo): env 0件 → 対象外
- `blog_data-career`: WordPress運用、Vercel外 → 対象外

デプロイ履歴に不審なアクティビティ無し（全て本人アカウントからの正規デプロイ）。

| # | 対応 | 結果 |

| 1 | `SUPABASE_SECRET_KEY` (service_role) を新キーへ差し替え | ✅ Sensitive化して登録 |
| 2 | Supabase 旧 Secret Key を Revoke | ✅ |
| 3 | 本番再デプロイ & Supabase依存API動作確認 | ✅ `/api/likes/top`, `/api/athletes/search` 等正常 |
| 4 | `VERCEL_DEPLOY_TOKEN` env削除（コード内で未使用、2026-03-25のDeploy Hook移行後のデッドコード） | ✅ |
| 5 | Vercel PAT `trails-jp-weekly-deploy` (Mar 4 作成, Never expires) を Revoke | ✅ |

### 意図的にローテしなかった項目

- `CRON_SECRET` — Cron認証用。service_role 無効化で主要リスク（DB書き込み悪用）が消滅。残存リスクはFunction枠消費DoSのみ
- `VERCEL_DEPLOY_HOOK` URL — Deploy誘発DoSのみ、コード改ざんは不可
- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_FORMSPREE_ID` — ブラウザバンドル済みの公開情報

### 教訓

- `!` プレフィックスはClaude Code REPL内のシェルパススルー機能。素のbashで `! cmd1 && cmd2` と書くと `!` が論理NOT演算子として働き、cmd1の終了ステータスが反転してチェーンが壊れる。ユーザーに手順を渡すときは実行環境を意識する
- 値をチャットに貼ると履歴に残るため、新キーは `vercel env add` のインタラクティブプロンプトで直接入力する運用に統一
- `vercel@51.8.0` は壊れた依存 (`@vercel/static-build@2.9.20` 不在) → `vercel@51.7.0` 固定で回避
