### 突合ロジックを変更するときの全件回帰検証手順（再利用可）

STOP_WORDS / EVENT_ALIASES / `fuzzyMatch` を触ると全件の突合が動く。必ず変更前後を突き合わせること。
オフラインで測った予測18件と本番実測18件が完全一致したので、この手順は信頼できる。

1. 本番 events ストアの全件を取り出す。`curl https://trailsjp.vercel.app/events` の RSC ペイロードから
   `joe_event_id` / `name` / `date` を抽出して `/tmp/joe_corpus.json` に置く
   （同梱の `src/data/events.json` は古く件数も少ないので使わない。2026-08-24 時点で 2,272 件 vs 2,508 件）
2. コーパスを読み、**`lapcenter_event_id` を持たせずに** `matchLapCenterEvents` を呼んで
   `joe_event_id -> lapcenter_event_id` の対応表を JSON 出力する使い捨てスクリプトを書く
3. `git stash push -- src/lib/scraper/lapcenter.ts` で変更を退避してベースラインを取る →
   `git stash pop` で戻して変更後を取る
4. 差分を「新規成立 / 消失 / 付け替え」に分類して全件確認する。**消失と付け替えは1件でも要調査**
5. スクリプトは削除する

**罠**: 退避が効いているかを必ず確認すること。並行セッションが変更をコミットしていると
`git stash` が HEAD = 変更後の状態へ戻すため、差分ゼロが「安全」ではなく「測れていない」を
意味することがある（2026-08-24 に実際に遭遇。ベースラインの `matched` 件数で気づいた）。

## Context

2026-08-24、`/results`（結果分析）に土日の大会が出ないという指摘から調査したところ、原因は cron 障害ではなく **JOY と LapCenter の大会名が `fuzzyMatch` で結び付かず、`lapcenter_event_id` が付かないまま一覧から落ちていた**ことだった。`/results` は `lapcenter_event_id` を持つイベントだけを一覧化する（`src/app/results/page.tsx:18`）。

該当3件は `MANUAL_LC_OVERRIDES` への手動追記で解消済み（`2e09133`）。しかし調査中に、これが単発事故ではないことが分かった。

- 中高選手権の本大会オープン競技は **2022年・2023年も未突合**
- 彩の森入間公園の体験会は **2024-04 以降の全30回が未突合**

突合は「同日 × 名前 fuzzy」の 1 経路しかなく、**失敗しても何も鳴らない**。だから何年も落ちたまま誰も気づけなかった。本当の問題は突合精度ではなく検知の不在であり、突合をどれだけ賢くしても新しい命名パターンは必ず漏れる。

このフェーズでは**漏れを検知して知らせる**ところまでを作る。突合精度の改善（EVENT_ALIASES 追加など＝フェーズ a）は本プランの範囲外で、検知を入れた後に着手する。

したがって「閾値を上げれば誤検出を減らせる」という計画時の見立ては誤り。閾値に上振れの余地はゼロで、この誤検出1件はメールに混じる前提とし、`MANUAL_LC_NO_MATCH` での個別ミュートで対処する。

## 決定事項

- 通知は**高確度（類似度 ≥ 閾値）だけメール**。全候補は admin ページで見る
- 誤検出の恒久ミュートは**コード定数**（`/admin` に認証が無く、画面から dismiss させると誰でも押せるため）
- 対象は**直近60日**（`tags` が生きている範囲と一致し、フィルタ精度が最も高い）

## 実装

### 1. 純関数の新規ファイル `src/lib/analysis/match-gaps.ts`

`src/lib/analysis/event-match.ts`（純関数＋専用テストの既存パターン）に倣う。ネットワークも DB も触らせない。

- `nameAffinity(a, b): number` — 正規化後の文字バイグラム overlap 係数
- `findMatchGaps(joeEvents, lcEvents, { now, windowDays }): MatchGapCandidate[]`

`MatchGapCandidate` は `joe_event_id` / `joe_name` / `date` / `joe_url` / 同日の未使用LC配列 / `affinity` / `tier`（`"likely" | "possible"`）。

判定順序:

1. `now - windowDays <= date <= now`（未来の大会は結果がまだ無いので対象外）
2. `lapcenter_event_id` が付いていれば除外
3. `MANUAL_LC_NO_MATCH` に載っていれば除外
4. `source === "dokori"`（どこオリ由来。合成ID かつ mulka2 とは無関係）なら除外
5. `tags` に `講習` / `ロゲ` / `SKI` / `どこオリ` を含むか、名前が除外キーワード（`中止` `延期` `研修` `講習` `オンライン` `報告会` `連絡会` `総会` `説明会` `表彰`）に当たれば除外
6. 同日の LapCenter イベントのうち、**どの JOY イベントにも割り当てられていない**ものを候補として集める。無ければ除外
7. 候補との最大 `nameAffinity` を取り、閾値以上を `likely`、それ未満を `possible`

閾値と除外キーワードは名前付き定数にする。

### 2. `src/lib/scraper/lapcenter.ts`

- `normalize` を export（`match-gaps.ts` が同じ表記ゆれ正規化＝全角半角・第N回除去・大学略称展開・イベント略称展開を再利用するため。ロジックの二重管理を避ける）。なお `normalize` は STOP_WORDS を除去しない（除去するのは `coreString`）。突合漏れの検知では「選手権」「体験会」のような共通語こそ手がかりになるため、STOP_WORDS を残した `normalize` を使うのが正しい
- `MatchResult` に取得済みの `lcEvents` を載せて返す（**再フェッチさせないため**。8年分＝2,528件を cron が既に取っている）
- `MANUAL_LC_NO_MATCH: Record<number, string>`（joe_event_id → 除外理由）を `MANUAL_LC_OVERRIDES` の隣に新設。実際の漏れを直す override 追加と同じデプロイに乗せられる

`matchLapCenterEvents` のジェネリック制約に `tags?: string[]` を optional で追加する。

### 3. `src/app/api/cron/sync-lapcenter/route.ts`

突合ブロックの直後に `findMatchGaps` を呼び、結果を payload の `match_gaps` に載せる（**上限20件**。`cron_log.result` の肥大を防ぐ）。`likely` が1件以上あれば `notifyCronWarning` でメール。

既存の watchdog チェックと同じく **非致命・完全隔離**（try/catch で握りつぶし、本処理の結果に影響させない）。検知の失敗で日次のスクレイプを止めては本末転倒。

デダブのシグネチャは `unmatched_lc_candidates:<likely な joe_event_id を昇順連結>`。候補集合が変われば即再通知され、変わらなければ24時間は抑止される。**未解決のまま放置すれば日次で再送される**のは意図した挙動で、止める手段は override 追加か `MANUAL_LC_NO_MATCH` 追記のどちらか。

### 4. `src/app/api/cron/sync-events/route.ts`

既存マージに `tags` の引き継ぎを追加する（新しい方が空で既存にあれば既存を残す）。2行。これを入れないと、アーカイブ落ちのたびに `tags` が消えてフィルタ精度が落ちる。

### 5. `src/app/admin/cron-status/page.tsx`

「突合漏れ候補」セクションを追加。**最新の sync-lapcenter の `cron_log.result.match_gaps` を読むだけ**で、LapCenter への再フェッチはしない（既存 `fetchRecent` の戻り値をそのまま使える）。

各候補に JOY 大会名（`joe_url` へリンク）・日付・同日の未使用LC候補（mulka2 へリンク）・類似度・tier を出す。`likely` を上に。件数0なら「候補なし」。

`src/lib/cron-status.ts` に表示用ヘルパを置く場合はそちらへ（ページに判定ロジックを書かない既存方針に従う）。

### 6. テスト `src/lib/analysis/__tests__/match-gaps.test.ts`

- `nameAffinity`: 上表の8ペアを fixture にして、閾値で真3件が `likely`・偽4組が `possible` 以下になることを固定する
- `findMatchGaps`: ウィンドウ外の除外 / `lapcenter_event_id` 済みの除外 / `MANUAL_LC_NO_MATCH` の除外 / `tags` と名前キーワードの除外 / 同日に未使用LCが無い場合 / 他 JOY に割当済みの LC を候補にしないこと

## このフェーズでやらないこと

以下は既存の作りの問題で、今回の差分が持ち込むものではない。フェーズ a のあとに別途扱う。

- `lapcenter_url` が override 側・自動マッチ側とも `file=1` 固定（結果が file=3 の大会で外部リンクがスタートリストを開く。突合済み約997件すべてに該当）
- `fetchSplitListDetailed` が HTTP 非成功を空配列で返し、cron は DB upsert エラーしか失敗と見ないため、部分欠損でも取込済みと記帳される
- `sync-lapcenter` が `readEvents()`（非 strict）を使うため、Storage 読込失敗時に古いバンドルでストア全体を上書きしうる（`sync-entries` は `readEventsStrict()` で fail-closed 済み）
- 過去分（2019-2025）の突合漏れの一括洗い出し。候補763件でノイズに埋もれるため、別の手がかりが要る
