# 結果分析ページ: mulka2 のクラスID の振り直しでリンク先が別クラスになる問題

- 作成: 2026-09-30 JST
- ステータス: **完了**（2026-09-30。PR #85 本番反映・本番で AL1 の移動を確認・ユーザー実機確認済）

## 事象
ミスの傾向の一覧から中高選手権 個人（2026-08-22, ev=9974）の AL1 のレッグを開くと、`/results/9974/12` が学校対抗クラス（1 レッグ・31 人・本人不在）を表示する。

## 原因
1. リンクは DB（`lc_leg_splits.lc_class_id`・8/24 取込）のクラスID を使う
2. 主催者が結果を再掲載し（JMF/JWF 追加・並び替え）、mulka2 のクラスID が振り直された: AL1 12→6、AL2 13→7、M18A 4→9、埼玉県立浦和高等学校 15→12 など
3. mulka2 のクラスID は不変ではないが、そのずれを検知する仕組みが無かった

## 範囲（2026-09-30 調査）
- 直近 40 大会の抜き取りで、実ずれは中高選手権 個人（9974）・団体（9976）の 2 大会。リレー 9983・とちトレ 9908 のずれは調査スクリプトの表の読み取り誤りの可能性が高い（未確定）
- 影響: DB のクラスID をそのままリンクに使う「ミスの傾向 → 結果分析」のみ
- 影響なし: 選手ページ → `/results/go`（クラス名で live 解決）、大会ページのクラス一覧（live）、DB の中身・ミスの傾向・難レッグ判定（クラスID はグループ化の鍵のみ）

## 対応
- `src/lib/results/class-id-drift.ts` `resolveDriftedClassId`: リンクの `cn`（クラス名）と今の classId のクラス名が違い、同名クラスがちょうど 1 つならその ID。一致・該当なし・複数・`cn` なしは null（そのまま開く）
- 結果分析ページ（`/results/[eventId]/[classId]`）: `cn` があれば上記で引き直し、ずれていればクエリを保ったまま正しい classId へ redirect。取得失敗時はそのまま開く
- クラス一覧のキャッシュを `src/lib/results/event-classes-cache.ts` に共通化し、1 日 → 1 時間（旧コメント「クラス一覧は不変」は誤り）。`/results/go` もこれを使う

## 検証
- vitest 1005 件緑（新規 5 件）・tsc 0・lint 0
- ローカル実描画（Edge 390px）: `/results/9974/12?...&cn=AL1` → `/results/9974/6` に移り「児玉 健」を特定・レッグ強調あり／名前一致の `/results/9601/1?cn=M21A2` は移らない

## 残（別件）
- 同姓同名の改名シム（`resolveAliasNameForLc`）も (大会ID, クラスID, 走者番号) を鍵にしているため、振り直しの大会では効かなくなる可能性がある。今回の 9974/9976 にはシムの登録なし（影響なし・確認済み）。今後シムを足す大会で振り直しが起きたら要注意
- ずれの定期検知（cron で DB と live のクラス名を突き合わせる）は未実装
