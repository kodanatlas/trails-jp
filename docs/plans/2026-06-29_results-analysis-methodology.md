> 対象読者: 東大OLK・京大・筑波・東北など強豪大学OB/現役。WinSplits / SplitsBrowser / Routegadget を日常的に使い、自分で Python/Excel でラップ解析と反省ノートを書く層。

## 0. 前提（地図がないという制約を最初に宣言する）

- スプリットデータには**地図・距離・登距離・GPSがない**。レッグ難度・長さは「フィールドのタイム分布」からのみ推定する。これを全ページに明記し、ルート幾何は一切断定しない。
- レッグタイムは**乗法的**（同じ10%のミスが長レッグほど多くの秒を食う）。距離で割れないので**全計算は対数空間** `y=ln(split秒)` で行う。生秒の加法モデルはレッグ長とミスを混同するため禁止。
- 方向規約は**サイト全体で1つ**: 速度系は `100=基準, 低い=速い=良い`（mulka2 legSpeed/speed と同方向）。WinSplits Performance Index（高い=良い）を同一チャートに混ぜない。**出荷前に「既知優勝者が全速度系指標で最小を返す」CIブロッキングのunitテストを必須化**（過去に方向逆実装した教訓の制度化）。

## 1. 差別化の核（3文）

1. **正直にマッチ**: 単一レース内の走力/ミス分離（頑健な個人ベースライン）と、レッグ基準・理想タイムの算出は SplitsBrowser(median-of-ratios)・WinSplits(長さ加重median PI)・mulka2(桜井・羽鳥メソッド)が既に高水準で実装済みの**コモディティであり、我々はそれを名指しで再現してマッチするだけ**——ここを新規性として売らない。
2. **再計算で超える点**: 我々の優位は (a) ハードコードした閾値でなく**混合モデル（クリーン対数正規＋片側ミス成分）でミス事後確率を推定**し小フィールドでも汚染に強いこと、(b) **n連動の不確実性提示と抑制**（4人クラスに偽の95%CIを出さない）、(c) **正直な要因未分離の明示**——この3点で「精密に見える嘘」を出さない統計的誠実さ。
3. **構造的な堀（単一レースツールが原理的に不可能）**: 選手アイデンティティに紐づく**クロスレース縦断**——同走力帯に対する相対ミス残差、局面×レッグ長×重大度のミス指紋、調子トレンド。ただしクロスレースの**絶対走力比較は地形交絡と対戦グラフ連結性で強く制限される**ため、これは「実験的・条件付き」として提示する（後述）。

## 2. 確定した方法論

### 共通基盤: 頑健二元対数分解（全プリミティブの脊椎）

各 event×class（**かつ後述のフォーク検出を通過したクラスのみ**）で、レッグ×走者の対数スプリット行列に Tukey median polish を適用:

```
y[i,l] = ln(split[i,l]) = μ + a[i] + b[l] + r[i,l]
```

- `a[i]` = 走者効果（走力, exp(a)低い=速い）, `b[l]` = レッグ時間尺度（**唯一の長さ/難度proxy**）, `r[i,l]` = 残差。
- median polish 採用理由: 行/列あたり高いbreakdown（1セルの外れ値で行・列推定が動かない）、欠損のある不均衡行列（DNF/MP）を補完なしで処理。検証で 132×23 のラギッド行列でも収束を確認済み。

**← 変更（レビュー1/3 must-fix）: median polish の非一意性に対処**
- スイープ順を**行→列固定**で文書化。`R medpolish` 行優先と回帰一致をCIゲートに入れる。
- 「~50%breakdown」は**完全表の主張であり、有効6レッグの疎行は当てはまらない**ことを正直に明記。疎行（MP除外後 <6 有効レッグ）の個人出力は**ハード抑制**。

### プリミティブ1: 個人ペース指数 P_i とレッグ基準 R_j

**最終定義（← 大幅変更: レビュー1 kill-shot「trim-then-threshold循環」を廃止）**

旧設計の「最速65%を片側トリム→残差からミス判定」は、トリムで中心が真のメディアン以下に引っ張られ、**クリーン走者に幻のミスを製造する**（合成クリーンフィールドで実証可能な自己成就バイアス）。これを廃止し、**混合モデル**に置換する:

各走者の対基準対数残差 `{r[i,l]}` を、
```
クリーン核   ~ N(ρ_i, σ_i²)        （日常的なレッグ間ばらつき, 両側）
ミス成分     ~ 片側重い裾（shifted-exponential 等, r>0側のみ）
```
の2成分混合として **EM で同時推定**。これにより
- 個人クリーンペース `ρ_i`（=走力の精緻化）と**ノイズスケール `σ_i` を同時に**得る（旧設計の「同じレッグからスケールも推定」という二重循環を解消）、
- 各レッグの**ミス事後確率 `π[i,l]=P(mistake|r)`** を返す（ハード閾値でなく確率）。

公開指数:
```
P_i = 100 · exp(ρ_i) / f_ref
期待レッグタイム ê[i,l] = exp(μ + ρ_i + b[l])     ※クリーン核中心を使用
対基準ロス(秒)  Δ[i,l]  = split[i,l] − ê[i,l]
```

**受入条件（← 検証由来の必須ゲート）**: 合成クリーンフィールド（iid対数正規・ミス0注入）で**フィールド全体の平均ミス率 ≈ 0** を満たすこと（優勝者だけでなく全員）。この合成校正を**方法論ページで公開**する。

**f_ref の正直な扱い（← レビュー1/検証 must-fix）**
- 旧 `f_ref = 最速k人(k=max(3,0.25n))のトリム平均` は **n≤12 で実質 k=3 = mulka2のAve3そのもの**。日本のクラスは大半が n≤12 なので、これは「我々が批判したAve3」と同型。
- **対処**: f_ref を**フィットしたペース分布の高分位（model-based, 例10–15%tile）**に置換し、k=3に退化させない。同時に**reverse-engineeringで判明した事実（mulka2のAve3は最小値ではなく上位3平均で、悪い基準ではない）を受け、「mulka2=最小値/superman」という旧批判文言を全削除**。
- `f_ref` アンカーにより **P_i は mulka2 巡航速度より約10–14ポイント低く出る**（"100"の定義が違う）。**P_i と 巡航速度はスケールが違うと明示**し、同一軸に並べない。

**recompute vs relay**: P_i / R_j / Δ は**再計算（ヘッドライン）**。mulka2 speed / legSpeed / Ave3 を muted な対照列で併記（後述§3）。
**relay生データ**: lapTime, lapRank, elapsedTime, elapsedRank, start, result, rank。

### プリミティブ2: タイム分解（理想 / 走力 / 残差）

**最終定義（← レビュー1/2 must-fix「ミス命名」を全面反映）**

```
CleanTotal_i = Σ_l ê[i,l]                       （自分のクリーンペースで全レッグ走った時の想定）
IDEAL        = Σ_l exp(μ + a_ref + b[l])         （フィールド共通の基準ペース定数・全員同じ）
走力Deficit_i = CleanTotal_i − IDEAL              （レッグ不変の系統的走力差, ≥0）
残差_i        = result_i − CleanTotal_i           （レッグ固有の対基準ロス）
厳密整合:  result_i = IDEAL + 走力Deficit_i + 残差_i   （構築上完全一致, 検証で max|err|=0.0s）
```

**← 最重要変更: 残差バーを「ミス」と呼ばない（レビュー2）**
ナビゲーション競技において、スカラーの `a[i]` は**地形タイプ別の走力（湿地・コンタ・植生・低視界での読図走）を吸収できない**。残差 = ミス + 地形×走者交互作用 + パック + コンディション + ルート選択コスト + ペース変動 で、地形交互作用項はミス項と同オーダー。
→ 画面ラベルは **「走力で説明できない残差（要因未特定）」** とし、内訳推定として「マップ照合候補レッグ」を提示。**個別レッグに「ナビミスN秒」と断定しない**。集約 `残差率` は出すが「ミス純粋でなく疲労・地形・ルートを含む」と毎回caveat。

**整合の正直さ（← レビュー1 must-fix）**: 「厳密に足し合う」ことは**走力/残差の分割の正しさを保証しない**（残差は定義上の引き算で、何でも吸い込む）。これをUIで明言。可能なら局面ドリフト項 `γ_i·(l/L)` で**疲労を第4セグメント「スタミナ」として残差から分離**（オプション）。

**relay/recompute**: 後述§3。**走力Deficit と IDEAL は mulka2 に対応物がなく、純粋に新規の加法レイヤー**（検証確認）。

### プリミティブ3: 残差検出 & クリーンレッグ分類

**← 変更**: ハード三重閾値（旧）から、**プリミティブ1の混合モデル事後確率 `π[i,l]` を一次情報**に。表示用に解釈可能な絶対秒 `Δ` と比率 `ρ` を併記。

- **多重比較を既定でFDR制御**（← レビュー1/3 must-fix。旧「FDR任意」は n=30×16=480セルで z>2 が1レース約11個の偽陽性を撒く）。1レースあたり期待偽陽性数を方法論ページに明記。
- **競技別閾値（← レビュー2）**: スプリント/短技術レッグは3–8秒の誤差で決まる。**universal 15–20秒フロアを廃止**し、discipline（forest/sprint, さらに可能ならmiddle/long）別に絶対フロアを設定。
- **疲労ドリフト ≠ 離散ミス**: 後半クラスタする残差はスタミナの可能性。離散スパイクとトレンドを分離、または明示caveat。
- **安全ルート ≠ ミス（← レビュー2）**: 慎重な安全走が、運の良い攻撃的走で決まった基準に対し正の残差になる問題を明記。「もっと攻めろ」と読ませない文言設計。

**個人ゲート（← 検証 must-fix C）**: 個人ペース/分類は**MP除外後の有効クリーンレッグ ≥6–8本**を必須。検証で DNF の数本"soft"レッグから `P_clean=16787` の異常値が出た。満たさなければレッグ生表示のみ。

### プリミティブ4: 決定的レッグ

**← 大幅変更（レビュー1/3 kill-shot「自己分散」＋検証）**

旧 `C(l)=Cov(split_l, Total)/Var(Total)` は `Total⊇split_l` ゆえ自己分散項が支配し、**生秒では実質「最長レッグ」を、1人の大事故では「その事故レッグ」を"決定的"と誤報**する。検証の n=6「leg5=70%」もこの人工物。

**最終定義**:
```
C(l) = Cov(split_l, Total − split_l) / Var(Total)     ※自己分散を除去
- 残差行列上で計算（生秒禁止）, 既定は表彰台/上位コンテンダー限定 (leave-self-out)
- ロバスト版: Spearman ρ(split_l, result) を併用
```
- **「このレッグでレースのX%が決まった」ヘッドラインは n≥~15 未満で禁止**。小nでは生分散ノート＋「1走者の事故の可能性」警告。
- 負の寄与（パック再集合）は隠さず符号付き報告。

**relay/recompute**: 100%再計算（mulka2はレッグ集約出力を持たない）。relay入力はlapTime/result/elapsedRank。

### プリミティブ5: ルートチョイス検出 → **「決定レグ内の探索的フラグ」に降格**

**← 大幅変更（検証B＋レビュー2 が両方 kill）**

検証実データ: 大フィールド2クラス**全40レッグでルートチョイス候補ゼロ**。bare max-gap ヒューリスティックは **17/17・23/23レッグで発火する偽陽性製造機**（最大ギャップは中央の反モードでなく遅い裾の2人外れ値に座る）。さらにレビュー2の指摘で**判別ロジックが逆**: (1) よく設定されたルートチョイスは時間均衡=単峰なので多峰検定が発火しない、(2) ルート選択は能力相関（強いナビゲーターが良ルートを選ぶ）なので `ρ_abil` は**高くなる**——「ルートチョイスは能力順を撹乱しρ_abil低」という前提は精鋭の実態と逆。

**最終方針**:
- ルートチョイスを**ヘッドライン機能にしない**。「決定レグ」の中で残差分散が高いレッグに **dip検定（n≥25のみ）** を補助的に走らせ、発火した稀なケースだけ**「ルートチョイス候補（地図要確認の仮説）」**と提示。地図がない以上、永久に仮説。
- Sarle BC / 2成分GMM / bare max-gap は**右歪に偽陽性するため不採用**（検証で 9877 L22: BC=0.90 だが ρ_abil=0.83 = 純粋歪み）。
- `b_l` とルート検出の鶏卵循環（レビュー3）も「だから単一値b_lはルート平均、純実行基準でない」とcaveat。

### プリミティブ6: クロスレース縦断（堀） — **二層に分離**

**← 変更（レビュー1/2/3 全員が α 単一スカラーを批判）**

問題: クロスレース走力 `α_i` を「共通対戦相手グラフのWLSで単一スカラー推定」する設計は、(a) 能力の**地形非推移性**（物理型 vs 技術型は地形で逆転）を無視、(b) effective-resistance CI は**連結性（分散）しか測らず地形交絡バイアスを測らない**ため、繋がっていれば「狭い・確信的・しかし間違った」走力差を出す、(c) 日本の対戦グラフは地域/大学でクリーク化・疎で**「比較不能」多発**、(d) **未検出パックが a_i を系統汚染**し全国gaugeを毒する。

**層A（堀の本体・出荷可）— 単一レースで識別可能な量のアイデンティティ集約**:
- **同走力帯に対する相対ミス残差**: コホート（同discipline・同連結成分・α±0.5SD or クラブ/年代）内で `残差率 ~ 走力` を回帰し、選手の標準化残差（「自分の走力相応より多く/少なくロスするか」）。これは単一レースツールが原理的に出せず、コーチング上actionable。
- **ミス指紋**: 局面（序/中/終盤）× レッグ長（b分位）× 重大度ヒストグラム × ミス後lag-1動揺。**FDR後の残差のみプール**（偽陽性が指紋に蓄積しないように）。
- **調子トレンド**: 信頼度加重 Theil–Sen/EWMA（旧2点最小二乗を廃止）、各レースを `1/Var(a_i,r)`（クリーンレッグ数×フィールドn）で重み付け、**reliable race <5 でトレンド線抑制**。

**層B（実験的・条件付き表示）— クロスレース絶対走力 α**:
- 地形random効果を追加し、**差分グラフの適合度（残差が構造化していれば誤特定）を必ず併記**。
- **連結性を実データで事前検証**（§5）し、高抵抗ペアは「比較不能」。地形同質性が確認できないペアの絶対比較は出さない。
- **「moat」と自称しない**。コーチング価値は層Aが担う。

**パック除染（← レビュー2/3 must-fix・堀の前段で必須）**: start再構成だけに頼らず、**3レッグ以上連続の異常同調（in/out両端近接）**で集団走を検出し、該当レースの走力寄与を強くダウンウェイト/除外。フォロワーの被牽引レッグを「クリーンナビの証拠」にしない。

**アイデンティティ誤マージ（← レビュー3）**: 旧姓/旧字体/通名の誤マージ・誤分割は1件で1キャリアを破壊。レビュー経路と大会ごと所属サニティチェックを必須。

---

### 横断: フォーク/バタフライ/リレー検出（← レビュー2 kill-shot, 新規必須）

フォークでは「レッグl」が走者ごとに物理的に別コントロール → 列lが別レッグの平均 → median polish が無意味。**スプリット構造が単一共通コースと矛盾するクラスを検出し、分解を出さず隔離フラグ**を立てる。リレークラスは原則対象外。これがないとリレー選手は初回で破綻解析を見て離脱する。

## 3. LapCenterモデルの扱い（reverse-engineering 確定版）

**← 全面書き換え（検証A＋逆解析が旧methodologyの2つの事実誤認を訂正）**

逆解析（近機械精度・class1 n=6でほぼ完全一致）で確定した mulka2 の実際の式:

| mulka2 metric | 確定した実式 | 旧methodologyの誤り |
|---|---|---|
| レッグ基準 | **Ave3 = 上位3スプリットの平均**（最小値でない・**DNF/MPのクリーンレッグも基準プールに含む**） | 「最小値/superman」は誤り |
| `legSpeed` | `round(100·lap/Ave3)` | — |
| `speed`(巡航速度) | 速いレッグから累積Ave3が50%到達まで採用しその区間の `100·Σlap/ΣAve3` | — |
| `legLossTime` | `lap − Ave3·(speed/100)` = **既に個人ベースライン**（behind-the-winnerではない） | 「naive behind-best」は過度に辛辣 |
| `totalLossTime` | `Σ max(0, legLossTime)`（正のみ） | — |
| **`idealTime`** | **`result − totalLossTime` = 各走者自身のミスなしタイム ≈ 我々の CleanTotal_i** | **「Σ min」も「Σ Ave3 composite」も誤り** |
| `lossRate` | `totalLossTime/result` | — |
| `totalRelative` | `round(100·result/ΣAve3)` ← フィールド合成基準はここに出る | — |

**結論（信頼性に直結）**:
- mulka2 のモデルは**実はかなり良い**（個人ベースライン・Ave3・DNFレッグ活用済み）。旧仕様の「mulka2を訂正する」「理想タイムは最速ラップ合計で楽観的」という**UI注記は事実誤認で、読者に1行で論破される（idealTime=result−loss は即検算可能）**ので**全削除**。
- 正しい対照マッピング: **CleanTotal_i ↔ idealTime / 残差_i ↔ totalLossTime / P_i ↔ speed（スケール差あり明示）**。同一構築物の**頑健版（混合モデル vs 50%カット）として横並び**で見せる。
- **DNFクリーンレッグ活用は mulka2 と同等（パリティ）であり新規ではない**。新規は「頑健推定＋n連動不確実性＋クロスレース＋加法IDEAL/走力Deficit」。

**relay（そのまま事実）**: lapTime, lapRank, elapsedTime, elapsedRank, start, result, rank。
**recompute（ヘッドライン＋mulka2併記）**: P_i, R_j, CleanTotal/IDEAL/走力Deficit/残差, 残差率, legレベルロス。理由は「mulka2は単一レース・50%カット・不確実性なし・クロスレース不可」であり、**「mulka2が間違っている」ではなく「同じ量をより頑健に・不確実性付きで・複数レースで」**という正直なフレーミング。

## 4. 信頼性UX（専門家が信じる透明性）

1. **デュアル数値**: 全再計算値の隣に mulka2 原値を muted 表示＋「なぜ違うか」1行（例: 「LapCenterは50%累積カットの単一レース推定。trailsは混合モデルで小フィールドの汚染に強く、不確実性を併記」）。**差分を隠さず機能として見せる**のが唯一の信頼構築。
2. **n連動抑制ゲート（分布フリー中央値CIで正当化）**:
   - `n<5`: 生スプリット＋mulka2 relay のみ。フィールド相対指標を一切出さない（n=4は自分の中央値すら95%CI不能=full range 87.5%）。
   - `5≤n<8`: 中央値＋広CI、ルートチョイス/多峰なし、決定レグはヘッドライン化しない。
   - `8≤n<15`: 頑健統計＋CI、決定レグは注意付き、ルートチョイスは出さない。
   - `n≥15–20`: BCa CI 許可。`n≥25–30`: dip検定許可。
   - **個人ゲート（直交）**: 有効クリーンレッグ ≥6–8。
3. **小nでも価値を出す（← レビュー3 must-fix・最重要）**: 日本のクラスは n=4–15 が常態で、ゲートだけだと「最も使う場面でreskinに退化」する。対策: **クロスレースで b_l（当該選手の過去の類似テレインのレッグ効果）を借用**して小nの基準を補強し、生スプリット＋計算済みの転換点注釈（リード変化・順位確定）を**model-freeな主役**として常時提供（これは n=2 まで有効）。
4. **不確実性の可視化**: 全再計算値に秒＆%のCIバンド。ゲート未満はグレーアウト＋「データ不足: 生スプリットのみ」を**機能として**表示（謝罪でなく）。
5. **再現性**: クリーン済みレッグ行列と μ/a/b/残差・混合モデルパラメータを CSV/JSON で公開。**ただし§2の循環バイアスを全部直してから公開する**（公開した瞬間に読者が再走させて偽ミスを発見するため）。合成クリーンフィールド校正結果も同梱。
6. **方法論ページ**: 対数空間の理由、median polish手順とスイープ順、混合モデル、Qn小標本補正、n-ゲート表（被覆数値つき）、MP/外れ値ルール、フォーク隔離、クロスレース連結性条件、「地図なし=ルートは仮説」を明記。**前提が破れる場所（小・異質フィールド、パック、フォーク、地形交絡）を正直に列挙**。

## 5. 残る論点（オーナー＋外部辛口レビュアーの判断を仰ぐ）

1. **「残差」をどこまで分解するか**: 地図がない以上、残差からナビミスを純粋分離できない。「対基準ロス（要因未特定）」止まりで価値が十分か、それともユーザーの**反省ノート照合（ground-truth）で適合率/再現率を校正**してミス検出を正当化しに行くか（レビュー3が強く要求・現状エビデンスゼロ）。**推奨: 最低1大会のケーススタディで当たり/外れを公開**。
2. **クロスレース絶対走力 α を出すか**: 地形非推移性＋疎グラフで「狭いが間違ったCI」のリスク。層A（相対ミス残差・指紋）だけで堀として十分か、層Bを実験ラベルで出すか、完全に伏せるか。**実データで最大連結成分カバレッジと代表的地域間ペアのCI幅を測ってから決定**（未測定）。
3. **小nレジームの主役指標**: クロスレースb_l借用が現実に小フィールドで安定するか未検証。借用が破綻する場合、小nで何を「非自明な価値」として出すか。
4. **混合モデルの同定性**: クリーン核/ミス成分のEMが n≤12 の少レッグで安定収束するか、事前分布/正則化が要るか。合成校正で要検証。
5. **競技別閾値の粒度**: forest/sprintの2分でよいか、middle/long/ナイトまで要るか（メタデータが取れるか）。
6. **4コモディティ層への投資配分（レビュー3）**: プリミティブ1–4は SplitsBrowser 等への微増分。リソースを層A（堀）に集中し、1–4は「薄く正直に」出す選択と集中をするか。

## 7. 外部レビュー（Codex / GPT-5.5）反映 — v1.1 修正

別系統の辛口レビュー（gpt-5.5・read-only）で、内部反証3名が見落とした**数学的 must-fix が2件**判明。方向性は「かなり良い」と評価。以下を v1.1 として確定する。

### must-fix 1（CRITICAL・数学的自己矛盾）: 決定的レッグの ΣC(l)=1 と leave-self-out の衝突
- 問題: §6 の CIゲートは `ΣC(l)=1` を不変条件にするが、§4 で自己分散除去のため式を `C(l)=Cov(split_l, Total−split_l)/Var(Total)` に変えた。**この形は一般に総和が1にならない**（Σが1になるのは self を含む `Cov(split_l, Total)/Var(Total)` だけ）。専門家に一発で突かれる。
- **確定対処**: 「このレッグでレースの**X%が決まった**」という百分率（パーティション）表現を **leave-self-out スコアには使わない**。leave-self-out C(l) は**決定度の順位付け/相対バー**専用とし、`ΣC(l)=1` 不変条件のテストは**撤回**（代わりに「優勝争いに効いたレッグの順位が妥当」「1人の事故レッグが過大評価されない」サニティテストに置換）。百分率が欲しい場面は別途、自己分散の影響を明記した上で**残差行列上の分散パーティション**として補助提示（n≥15のみ）。

### must-fix 2（CRITICAL・座標系の曖昧さ）: median polish の `a[i]` と EM の `ρ_i` の関係未定義
- 問題: 走力を `a[i]` とするのか `a[i]+ρ_i` とするのか、`ρ_i` が `a[i]` を置換するのかが不明で、`P_i` と `CleanTotal_i` の座標系を読者に説明できない。
- **確定対処（座標系を一意化）**: 走力の座標は **median polish の行効果 `a[i]` ただ1つ**に固定する。EM は**残差 `r[i,l]`（既に `a[i]` 除去済み・クリーン中心≈0）に対してのみ**走らせ、その役割は**ミス事後確率 `π[i,l]`（片側裾）の推定に限定**する。すなわち:
  - `ρ_i` を**独立の走力項として加算しない**（二重計上の解消）。`ρ_i` は残差クリーン核の中心（≈0）に過ぎず、必要なら median polish の追加スイープで `a[i]` に吸収する。
  - 公開指数を **`P_i = 100·exp(a[i]) / f_ref`**、**`ê[i,l] = exp(μ + a[i] + b[l])`** に統一（`ρ_i` 表記を廃止）。
  - これにより `CleanTotal_i = Σ_l ê[i,l]` と `P_i` が同じ `a[i]` 座標で一貫する。**合成クリーンフィールド校正（全員ミス率≈0）でこの一意化をロック**する。

### Codex が「妥当」と確認した点
- 対数空間 + median polish + n連動ゲート + 「残差をミスと断定しない」方針。
- **mulka2 を悪者にしない再フレーミング**（`idealTime = result − totalLossTime` を認め、trails は「同じ量の頑健版・不確実性付き」と位置づける）が**最も信用される**。
- `n<5` は relay のみ、が正しい判断。

### Codex の出荷優先度（内部統合と一致 → 確定ロードマップに採用）
1. **最優先**: per-leg ingestion（パーサ改修）＋ **mulka2 再現テスト**を固める（全ての土台）。
2. 次に **n≥15 のみ** median polish 系の再計算を出す。
3. **EM混合 / クロスレース絶対走力 α / ルートチョイス推定は feature flag・実験表示で十分**。
4. **小n（n=4–15が常態）の主役**は統計モデルでなく、**順位変動・リード変化・mulka2値との見やすい比較・CSV公開**（model-free、見抜かれない事実ベース）。
5. **層A（同走力帯への相対残差・ミス指紋）は出す価値あり**＝堀。**層B（絶対走力 α）は v1 では出さない**（地形交絡＋対戦グラフの疎さで「狭いが間違った比較」のリスク大）。

### v1.1 の結論
方向性は確定。コモディティ層（単一レースの走力/ミス分離）は**薄く正直に・mulka2併記で**出し、リソースは**層A（クロスレース相対分析）＝堀**に集中する。実装は **Phase 0（per-leg ingestion + mulka2再現テスト）から着手**し、model-free のレース展開図・relay表・区間賞を Phase 1 の主役（全nで成立）に据える。

## 8. オーナー確定事項（2026-06-29）

- **ビルド順・Layer B 伏せ・優先度**: §7 の確定ロードマップで承認。
- **「ミス」の定義 = タイムのみ（地図・正解照合は不要・人手ゼロ）**: オーナー（強豪選手）裁定。「ミス＝レッグタイムがトップ3（Ave3）比で遅ければミスと見なす」のがコミュニティ共通定義。よって §5.1 の ground-truth 校正は**不要**として閉じる。
  - **オーナーの手動処理は一切入れない**（オーナーは毎レース参加するわけでなく、手間もかけない）。ミス検出・全分析は **LapCenter データから完全自動（cron駆動）**。人手の校正・確認ステップをパイプラインに入れない。妥当性は §4 の合成クリーンフィールド校正（自動）＋ mulka2 再現テストで担保する。
  - **影響（命名）**: §2 プリミティブ2/3 の「対基準ロス（要因未特定）」という過度な言い換えを緩和し、**コミュニティ標準どおり「ミス」と表記してよい**（読者が日常的に使う語）。ただし「パック・地形・コンディションを含みうる」旨の軽い注記は残す（rigor の頑健推定・n連動・クロスレースの価値は不変）。
  - **未確定の1点（Phase 2 着手前に確定。Phase 0/1 は非依存）**: トップ3比を (A) 生 `lap − Ave3` とするか (B) 巡航ペース補正 `lap − Ave3×(speed/100)`（= LapCenter ミス率 と同式・走力とミスを分離）とするか。**推奨 (B)**。
- **検証で確定した LapCenter 実式（§3）はそのまま採用**。Phase 0 の mulka2 再現テストでこの式群を回帰固定する。

### 8.1 方針転換（オーナー裁定2026-06-29）: relay-first（LapCenterの値をそのまま使う）

オーナー指摘「ミスのタイムは LapCenter データに載っている（`legLossTime`）ので、それを見ればミスと判断できる」。→ **単一レースのミス判定は LapCenter の `legLossTime` / `totalLossTime` / `lossRate` を relay** し、独自再計算しない。((A)/(B) フォークは LapCenter 値＝補正済み(B) で自動決着。)

- **重い再計算機構（median polish / EM混合 / 独自 P_i・CleanTotal/IDEAL/走力Deficit）は単一レースのヘッドラインから外す**＝将来のオプション/実験 flag（不確実性バンドやクロスレース正規化など、relay だけでは出せない所に限定）。Codex の「recompute は n≥15・EM は flag」をさらに前進させ、**v1 は relay 中心**。
- **relay する LapCenter 値**（per-leg 配列＋スカラー）: `lapTime / lapRank / elapsedTime / elapsedRank / legLossTime / legSpeed / start` ＋ `result / rank / speed / lossRate / idealTime / totalLossTime / totalRelative`。
- **差別化（LapCenterに無いもの）に集中**:
  1. **プレゼンテーション**: レッグカード（どこで何秒ロス＝legLossTime可視化）・レース展開図（elapsedRank/トップ差）・決定的レッグ・区間賞（lapRank==1）。いずれも relay 値ベースで全nで成立。
  2. **クロスレース縦断（堀）**: LapCenter の per-race `lossRate`/`legLossTime` を**選手横断で集計**＝ミス指紋（局面×レッグ長×重大度）・調子トレンド・同走力帯比較。単一レースの LapCenter には原理的に不可能。
- **mulka2 再現テストの役割**（変更）: 「独自式の検算」から「**パースの正しさ＋値の意味の固定**」へ。`idealTime = result − totalLossTime`、`legSpeed = round(100·lap/Ave3)` 等の恒等式で**パース結果の健全性を回帰チェック**する（数値の理解が崩れていないことの保証）。
- **rigor 成果の残存価値**: メトリクス方向の罠回避、mulka2を悪者にしない正しいフレーミング、フォーク/リレー隔離、n連動の不確実性提示、そして「堀＝クロスレース」という戦略判断。これらは relay-first でも全て生きる。

## 10. 追記（2026-07-07・Stage 2a/2b 実装時の確定事項）

- **⑤決定的レッグ → 「順位が動いたレッグ」として出荷**（PR #34/#35）。C(l)=Cov(R_l,T−R_l)/Var(T) は「1本のレッグで決まったレース」を構造的に見逃すため（外部レビュー指摘）、**主指標を elapsedRank の平均変動（記述統計）に変更**し、C(l) は「ミス残差の連動」の副指標（折りたたみ・相対バーのみ）に降格。百分率表現なし。
- **⑥ミス指紋 → 「ミスの傾向（クロスレース）」として出荷**（Stage 2b）。本文 §153 の「FDR後の残差のみプール」は混合モデルの per-leg 事後確率を前提とした要求だが、**relay-first（§8.1）では per-leg の仮説検定が存在しない**（ミス＝決定的閾値判定）。よって多重性の制御は**セルレベル（局面3×レッグ長3）のレース層別 permutation 検定＋BH-FDR（q=0.10）に置換**した。permutation は各レースのミス総数を固定してレッグ割当を並べ替えるため、レース内相関・日次調子を帰無分布に保存する（exact 二項の独立性仮定破れを回避）。
- ミス閾値は loss ≥ max(FLOOR_d, 0.30×(lap−loss))（FLOOR=罠レッグと同値）。0.30 は実測ミス率に較正した**運用上の規約**であり「真のミス」の推定ではない（params 公開）。
- パック除染は §161 の「in/out両端近接の3レッグ以上連続」を境界 run で厳密化し**両者対称除外**（リーダー/フォロワー識別なし）。除外の非無作為性は明記し、除染 ON/OFF 感度分析（フラグ一致率 99.1%）で頑健性を確認。
- 調子トレンドの信頼度加重（§154）は w=クリーンレッグ数×min(出走規模,20) で実装（フィールドn の情報飽和により頭打ち）。EWMA は不採用。
- 層Aの残り（同走力帯コホート版指紋・フォーク構造検出）と層Bは引き続き未実装。
