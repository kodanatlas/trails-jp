# バッチ5: /events 全件表示の増分レンダリング

- 作成: 2026-07-06 JST
- ステータス: 実装完了（本番確認は PR マージ後に追記）
- 前段: `2026-07-06_events_performance.md`（バッチ4）で発見した既存問題

## Context

/events でフィルタ「すべて」（2,400件超）にすると全カードを一括マウントし、リスト⇄カレンダー切替やフィルタ変更でタブが30〜60秒フリーズしていた（本番実測）。

## 実装（`src/app/events/EventList.tsx` のみ）

- `INITIAL_VISIBLE=150` / `LOAD_MORE=150` の増分レンダリング（依存ライブラリなし）
- `visibleCount` state＋`filtered`/`viewMode` 変化でリセット（**viewMode リセットは必須**: 全件ロード後にカレンダー→リスト復帰で全件再マウントしてフリーズするのを検証中に実測）
- 末尾「さらに表示（残り N 件）」ボタン＋ IntersectionObserver（rootMargin 600px）で自動追加ロード
- カレンダーモードは当月描画のみで軽いため無変更

## 検証（ローカル prod・実ブラウザ）

- 「すべて」切替: 従来30秒級フリーズ → **即描画**（150件・2272件表示・ボタン「残り2122件」）
- ボタンクリック 150→300、実スクロールで observer 自動ロード 300→450 を確認
- リスト(450)⇄カレンダー往復即応答・デフォルト表示（150件以下）はボタン非表示で従来同一
- tsc clean・vitest 552 green・build 成功
- 注: viewMode リセット追加後のフル再検証は SW キャッシュ再配信・ツール側 API 過負荷でローカル完走できず（1語の依存追加・同メカニズムはフィルタ変更側で動作実証済み）→ 本番マージ後に「すべて→全件スクロール→カレンダー→リスト」を最終確認する

## 検証中に発見した周辺事象（本 PR スコープ外・記録のみ）

- バンドル events.json に空文字タグのイベントがあり、タグ select に空 option が出る（データ由来・実害小）
- dev/ローカル検証時は SW（trails-jp-v2 cache-first）が旧チャンクを配信して新コードが動かないことがある → 検証前に SW unregister＋caches 削除＋ハードリロード（既知の罠の再確認）
