# 同姓同名の分離: 山田和輝（＋再発検知）

ステータス: 実装済み・DB 移行は push 後に実行（2026-11-04）

## 発端
補正済みポイントの再較正（2026-11-04）のレビューで、「同姓同名の別人が1人に合算される」既知の問題を確認した。ユーザーから「対応すべき」との指示（2026-11-04）。

## 現状（2026-11-04、本番ランキング 77 ファイルで調査）

検出方法は2つ。
- 同じランキングファイルに同じ氏名が2行ある → JOY が別人として扱っている
- 同じ氏名・別の所属で、同じ大会に違う得点が付いている → 別人

結果、該当は **山田和輝** の1組だけだった（鈴木健太は 8/31 に分離済み）。

| | KOLC の山田和輝 | 神大olk の山田和輝 |
|---|---|---|
| ランキング | M21・無差別・M21E・S_Open（F 7931 / S 8828） | M20・無差別（F 5495） |
| 出場 | 2025〜。インカレ・セレ等 | 2026-10-10/11 トータス50周年 Day1/2 のみ |
| 同じ大会での得点 | トータス Day1 2317・Day2 2566 | Day1 1963・Day2 1834 |
| LapCenter（lc_performances） | 74 行すべて | 0 行 |

### LapCenter 74 行をすべて KOLC 側とする根拠
- 2019年の愛知の大会（M15・名椙）から 2023 若桐杯ビギナー（大学1年）、2023〜24 の名椙・岡崎・根の上（愛知）へと続く。関東の大学大会と愛知の大会が同じ人物の履歴として連続している。
- 神大olk 側の出場はトータス50周年だけで、LapCenter に載っていない。

### 検出の限界
- 同じ大会に出ていない同姓同名は、得点の食い違いが無いので検出できない。
- 年齢別クラスは JOY の仕様上、若年者が M15/M18/M20 に重ねて載り、女子も M クラスに載るため、手がかりに使えない。

## 計画

### A. 山田和輝の分離（8/31 の改名シム方式を踏襲）
1. `src/data/athlete-aliases.json` に追加する。
   - KOLC → `山田和輝（KOLC）`
   - 神大olk → `山田和輝（神戸大学）`
   - 表示名は要確認（下記）。
2. DB の一回限りの移行 SQL `scripts/migrations/2026-11-XX_split-yamada-kazuki.sql` を作る。
   - `lc_performances` 74 行と、それに対応する `lc_leg_splits` 行を、主キーを明示して KOLC 側の表示名へ UPDATE する。
   - 8/31 の SQL と同じ構成にする（行ロック、件数とidの事前検証、トランザクション）。
   - cron が動いていない時間帯に実行する。
3. 反映の順序
   - push（ランキングの改名はビルド時に適用）→ ビルド完了 → 移行 SQL を実行。
   - 2つがずれる間（約10〜15分）は、KOLC 側の選手ページで LapCenter のカードが空になる。
4. 確認
   - 2人のページがそれぞれ正しい履歴を出す。
   - `/api/lc/山田和輝（KOLC）` が 74 件を返す。
   - 補正済みポイントがそれぞれの値になる。

### B. 再発の検知（新規）
- ビルド時に上の2つの方法で同姓同名の候補を検出する。対応表に未登録のものは、ビルドログに警告を出し、`/admin/cron-status` に「同姓同名の候補」として表示する。
- 自動で分離はしない（所属の表記ゆれや移籍を人が確認するため。8/31 の判断を踏襲）。
