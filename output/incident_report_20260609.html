エグゼクティブサマリー

選手ページ（/analysis）の「大会エントリー状況」カードに、一部の大会のエントリーが表示されない事象が報告された。当初は「上園久美子」「辻悠佳」など女性選手で目立ったため性別依存の不具合が疑われたが、調査の結果原因は性別とは無関係で、外部連携先 JOY（japan-o-entry.com）のHTMLフォーマット変更に起因する日付パースの不具合であることが判明した。

JOY がトップページの日付表記を「年あり」から「年なし（6/14 形式）」に変更し、行の date 属性も廃止したため、当サイトの日付パーサが近接大会の日付を date=""（空）にしていた。空日付の大会は日次バッチ sync-entries の date >= today 絞り込みから大会まるごと脱落し、その大会に登録した選手（男女問わず）のエントリーが索引に載らなかった。

根本原因のパーサを修正し、横展開・下流影響を多角的に監査のうえ、関連する潜在不具合も併せて修正した。本番反映はデプロイ＋日次cron 1サイクルで自然回復する。

1. 事象（症状）

  • 選手ページ「大会エントリー状況」に、実際には JOY でエントリー済みの大会が表示されない。
  • 報告例（いずれも JOY の実エントリーと本番表示の食い違い）:

2. 根本原因

外部連携先 JOY（japan-o-entry.com）がトップページのHTMLを変更した。具体的には:

  1. 各イベント行の date / date-sort 属性を廃止。
  2. 直近〜約6ヶ月の大会の日付セルを年なし表記に変更（例 6/14 (土), 6/20 - 21）。約6ヶ月より先・年跨ぎの大会のみ 2026/ 12/13, 2027/ 1/9 と年を明示。

当サイトの日付パーサ parseDateWithAttr（src/lib/scraper/events.ts）は4桁の年が無いと date="" を返す実装で、年なし表記の近接大会の日付がすべて空になっていた。空日付の波及:

JOY HTML変更（年なし＋date属性廃止）   └▶ parseDateWithAttr が近接大会を date="" に（トップ100件中 91件が空）      └▶ sync-entries が e.date >= today で絞り込み → 空日付の大会がまるごと脱落         └▶ entry-index.json にその大会のエントリーが作られない（男女問わず）            └▶ /api/athletes/[name]/entries が空 → 選手ページ UpcomingEntries に出ない

性別非依存であることの実証

東大OLK(2264) には男女合計807名（男598・女209）が登録。男女それぞれ3名を抽出し本番APIを確認したところ、6名全員が当該大会を本番索引に持っていなかった。すなわち「日付が空になった大会」が単位で脱落しており、性別は無関係。報告された2名がたまたま「日付が空だった大会（東大OLK等）」に登録していた女性だったため、性別パターンに見えていた。

なぜ大会によって出たり出なかったりしたか

sync-events は既存データの非空日付を温存する（if (!event.date && existing.date)）。このためフォーマット変更前に年付きで取得済みだった大会（例: さくらんぼ 2500）は日付を保持し、変更後に初出した近接大会（例: 東大OLK 2448/2264）だけが空日付のまま残った。これが「上園久美子はさくらんぼ1件だけ出る」症状の説明となる。

4. 対応内容（実施した修正）

① 根本原因: 年なし「M/D」の年を補完

「今日に最も近い年（前年/今年/翌年）」を選ぶ inferYearForMonthDay を追加し、年なし日付に年を補完。JOY は直近〜半年の大会のみ年を省くため、最近接年で一意に定まる（JST基準）。

function inferYearForMonthDay(month, day) {
  const nowJst = new Date(Date.now() + 9 * 3600 * 1000);
  const cy = nowJst.getUTCFullYear();
  const todayMs = Date.UTC(cy, nowJst.getUTCMonth(), nowJst.getUTCDate());
  let best = cy, bestDiff = Infinity;
  for (const y of [cy - 1, cy, cy + 1]) {
    const diff = Math.abs(Date.UTC(y, month - 1, day) - todayMs);
    if (diff < bestDiff) { bestDiff = diff; best = y; }
  }
  return best;
}

② 潜在不具合: 年跨ぎレンジの開始年補正

年なしレンジ 12/27 - 1/3 のような年跨ぎは、開始日(12月)を最近接年で丸めると過去年に倒れる。「終了日が今日以降になる最小の開始年」を採る startYearForCrossingRange で補正（現データでは未発火だが、年末年始シーズンに向けた予防）。

③ 受付状態の取りこぼし: 締切カウントダウンを open に

JOY は受付中の大会を「受付中」だけでなく あと N 日（締切カウントダウン）でも表示する。従来はこれを none（バッジ非表示）にしていたため、締切間近の受付中大会15件が「受付中」と認識されていなかった。これを open に分類するよう拡張。

const entry_status =
  statusText.includes("受付中") || /あと\s*\d+\s*日/.test(statusText)
    ? "open" : statusText.includes("締切") ? "closed" : "none";

④ 堅牢化: 不正な月日の排除

年なしパースに 月≤12 / 日≤31 のバリデーションを追加。将来 JOY が日付セルに余分な数字を入れても、13/14 のような不正値を誤った日付に変換せず空に倒す。

⑤ 退行防止: 手動スクリプトの整合

scripts/scrape-events.mjs の日付パースを本番（events.ts）と同一ロジックに揃え、冒頭に「本番cronが正・両者を同時更新すること」の警告コメントを追記。手動再生成による退行を防止。
